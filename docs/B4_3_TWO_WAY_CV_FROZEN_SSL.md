# B4.3 — Two-way cross-validated target-wise frozen-SSL classifiers

## Motivation

B4 produced the strongest frozen-feature OOF result so far, but each target chose its policy from a single inner fold containing only about 18–20 gold studies. B4.1 and B4.2 showed that forcing policies to be shared across all targets or broad pathology groups removes too much target-specific flexibility.

B4.3 keeps one policy per target but stabilizes selection. For an untouched outer fold, the two remaining gold folds are used symmetrically:

1. train candidate on non-outer fold A and predict non-outer fold B;
2. train the same candidate on B and predict A;
3. concatenate both held-out prediction blocks;
4. compute target AUC over all non-outer studies (about 38–40 gold studies);
5. choose that target's policy by this two-way CV AUC only;
6. refit the selected target classifier on all non-outer gold studies;
7. predict the untouched outer fold once.

Outer labels are never used in policy selection.

## Representation

B4.3 reuses `runs/b4_frozen_ssl/gold_features.npz` generated by the competition-only SSL ConvNeXt encoder. The encoder remains frozen and is not retrained.

## Candidate grid

The original B4 grid is unchanged:

- feature mode: `all`, `prior`
- PCA dimensions: `4`, `8`, `12`, `16`
- logistic-regression `C`: `0.1`, `1.0`

No new hyperparameters are introduced.

## Run

```bash
rsna-knee-b4-crossval \
  --config configs/train_local_ssl_strong.yaml \
  --features runs/b4_frozen_ssl/gold_features.npz \
  --out-root runs/b4_3_crossval_ssl \
  --n-bootstrap 5000
```

Outputs include per-fold OOF predictions, target policies with CV AUCs, bootstrap files, pooled `oof.csv`, `evaluation.json`, and `policy.json`.

## Interpretation

B4.3 directly tests whether B4's main limitation was variance from selecting target policies on only one tiny inner fold. It preserves pathology-specific downstream modeling while increasing the effective policy-selection validation set without leaking outer labels.
